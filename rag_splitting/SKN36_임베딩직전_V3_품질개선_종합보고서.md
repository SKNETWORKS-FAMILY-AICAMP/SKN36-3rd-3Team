> **검증 대상:** 사용자가 업로드한 `SKN36-RAG-Splitting(1).zip` 내 입력 JSON/JSONL 4개. 실제 데이터를 이용해 V3 코드 및 노트북 Run All 재실행.

> **중요:** 임베딩과 Qdrant/Neo4j 실제 적재는 하지 않았음.

## 2. 실제로 개선한 내용

1. **Markdown 표 분리 문제:** 표 블록의 머리글, 행 제목, 연도·열 레이블을 정규화한 `markdown_table_row` 청크로 변환. 복잡한/긴 셀도 표 제목·행/열 이름을 반복하면서 최대 700자 내에서 분할. **표 검색 카드 1,042건, 원본 표 행 1,024건** 식별.
2. **기초연금 연도·금액 분리 사례:** 2025년(현행) `342,510원`과 2026년(개정안) `349,700원`이 각각 연도 이름을 동반하는 같은 표 검색 카드에 포함됨. 원문 PDF 대조에 의한 공식 승인과는 다름.
3. **페이지 출처:** PDF 청크 2,314건은 복수 페이지 범위로 남겨두며, 단일 인용 페이지를 추정하지 않음. 원본 PDF를 넣으면 텍스트 앵커 후보 매칭을 지원하지만 `approved`로 자동 변경하지 않음.
4. **고령층/지역 판정:** 정책 1,946개에 대해 `policy_region_review.csv` 생성. 시도·시군구 문자열은 `hint`로만 취급하고 `region_filter_allowed=False` 유지.
5. **경기 지자체 미수집 485건:** `local_detail_missing_review.csv` 목록 추출. 없는 자격·혜택·금액·신청방법을 생성하지 않음.
6. **금액·표 검수:** `pdf_financial_review.csv`에 **506개 섹션**을 원본 대조 대상으로 추출.
7. **정책–PDF 연결 후보:** 564개의 명시적 정책명 문자열 일치 후보를 생성하고 `approved=False` 설정. Neo4j 승인 관계 자동 생성하지 않음.
8. **PDF 5번째/중복:** 원본 또는 전처리 섹션이 추가되면 자동 탐색·처리하고 종합 PDF의 정확 중복 가능성을 검토 큐로 분리. **이번 ZIP에는 실제 5번째 원본이 없어 미실행.**
9. **오프셋 정확성:** 일반 텍스트 분할에서 좌우 공백을 제거한 뒤 실제 시작·끝 오프셋을 저장. 표 청크는 원문 행 위치를 가리키며 `offset_mode=source_table_row_range`로 구분.
10. **토큰 검증 장치:** 임베딩 모델 토크나이저를 지정하면 `transformers`를 이용해 전체 청크를 전수 검증. 모델 미선정 상태에서는 **검증 완료라고 주장하지 않음**.
11. **불변성·참조 검증:** 사용자 ZIP의 네 입력 파일 SHA256을 현재 입력과 비교해 모두 일치함. Qdrant 포인트 UUID가 Neo4j `Chunk.id`에 존재하며 그래프 관계가 고아 노드를 참조하지 않음을 검사.
12. **Jupyter 실행:** 수정 노트북의 **Run All 실제 실행 성공**; 터미널 실행과 동일한 통합 Python 함수를 호출.

## 3. 남은 실제 데이터 한계 (자동으로 해결할 수 없음)

| 항목 | 현재 상태 | 해결 조건 |
|---|---|---|
| 다섯 번째 노령층 분권 PDF | **미반영** | GitHub `feature/10-api-data-processing/data/raw/pdf/`에서 실제 원본 파일 다운로드, `splitting_inputs/`에 배치. 임시 추출 후 원문 섹션 검수 필요 |
| 경기 지자체 상세 485건 | **미수집** | 유효한 API 키·일일 호출량·재수집 및 응답 검증 필요 |
| 정책 1,946건의 지역 적용 승인 | **0건 승인** | 공식 정책 문구/지자체 적용 범위 대조. `sido_name`만으로 확정 금지 |
| 표·금액·예외 공식 확인 | **검수 대기** | PDF 원본의 해당 페이지/표와 비교하고 승인해야 함 |
| 특정 페이지 정확성 | **공식 승인 0건** | PDF 4종 원본 반입 및 페이지 매핑 후보 검수 |
| 추출기가 만든 `- 행 / - 열` 형태의 복잡한 표 | **검수 대기** | 원본 PDF 레이아웃 대조, 필요 시 해당 표 수동 재구성 |
| 5종 PDF 간 실질 중복 판정 | **보류** | 노령층 분권 원본 투입 후 검토 큐 승인 |
| 최종 모델별 토큰 상한 | **미확인** | 사용할 임베딩 모델·토크나이저 선택 후 CLI `--tokenizer-name` 재실행 |
| 정책↔PDF의 공식 동사업 관계 | **승인 0건** | `policy_pdf_link_candidates.jsonl`에서 사업/대상/기준연도별 사람이 확인 후 별도 승인 데이터 생성 |

**따라서 최종 결과는 `임베딩용 기술적 입력 후보 생성 완료`이지 `공식 자격/금액 검수 완료`가 아닙니다.**

## 5. 권장 사용법

ZIP 안의 `splitting_inputs/`와 `splitting_output_v3/`는 실제 데이터 입력과 V3 재실행 결과입니다. 

**새 프로젝트에 직접 실행:**

```powershell
cd "C:\Dev\project\project 3st\SKN36-RAG-Splitting"
uv run --no-project python .\SKN36_auto_splitting.py --input-dir ".\splitting_inputs" --output-dir ".\splitting_output_v3" --strict-counts
```

Jupyter에서는 `SKN36_Policy_PDF_Splitting_Qdrant_Neo4j_임베딩직전_V3.ipynb`를 열어 Run All 실행. 기본 입력 경로는 프로젝트의 `splitting_inputs/`입니다.

**중요:** 기존 `splitting_output/` 폴더는 **덮어쓰지 않고** `splitting_output_v3/`에 새로 저장합니다. GitHub 업로드 시 `.venv`, `.env`, API 키, 캐시는 제외하세요.
