# SKN36-3rd-3Team

## 고령층을 위한 친절한 정책 안내 RAG 챗봇

고령층이 복잡한 정책·복지 정보를 쉬운 말로 이해할 수 있도록 돕는 팀 프로젝트입니다. 공식 정책 문서와 데이터셋·API에서 필요한 근거를 검색한 후 답변하는 RAG(Retrieval-Augmented Generation) 방식을 활용할 예정입니다.

현재는 기획 및 데이터 조사 단계입니다. 챗봇 구현, 데이터 확보, 모델 선정은 아직 완료되지 않았습니다.

## 목표와 답변 원칙

- 정책의 지원 대상, 지원 내용, 신청 방법과 문의처를 쉽게 설명합니다.
- 지역·연령·신청 기간 등 조건을 확인하고, 모르는 조건은 추가 질문합니다.
- 답변에 공식 출처 링크와 자료 기준일을 표시합니다.
- 검색 근거가 부족하거나 오래된 경우 확인이 필요하다고 안내합니다.
- 수급 자격을 임의로 확정하지 않고 공식 기관의 최종 확인을 안내합니다.
- 큰 글씨, 짧은 문장, 단계별 안내를 고려합니다. 구체적인 화면 구성은 팀 회의에서 결정합니다.

## 예정 처리 흐름

공식 데이터 수집 → 정제 및 출처 기록 → 문서 분할 → 임베딩 및 검색 인덱스 구성 → 질문 관련 근거 검색 → 쉬운 말로 답변 및 출처 표시

## 시작하기

1. Python 가상환경을 생성하고 활성화합니다.
2. `python -m pip install -r requirements.txt`로 초기 후보 의존성을 설치합니다.
3. `.env.example`을 `.env`로 복사하고 본인 키를 입력합니다.
4. `docs/data-sources.md`에 자료 조사 결과를 기록합니다.

현재 실행 가능한 챗봇 진입점은 없습니다. requirements는 초기 후보 목록이며, 팀 환경에서 호환성을 검증한 뒤 버전을 고정합니다. 모델·벡터 저장소·UI 기술은 회의에서 확정합니다.

## 협업 방법

1. Issues에서 할 일을 확인하고 담당자를 지정합니다.
2. Projects를 사용하는 경우 이슈를 해당 보드에 추가하고 Status를 Todo로 설정합니다. 자동 추가 설정이 없으면 이슈 생성만으로 Todo에 들어가지 않습니다.
3. 작업 시작 시 In Progress로 변경하고 `dev`에서 `feature/이슈번호-작업명` 브랜치를 만듭니다.
4. 문서 또는 코드를 작성한 뒤 `dev` 대상으로 PR을 생성합니다.
5. PR 본문에 관련 이슈를 연결하고 리뷰·병합 후 이슈와 보드를 완료 처리합니다. 기본 브랜치가 dev이므로 이슈 자동 종료 여부도 확인합니다.

API 키, 개인정보, 사용 권한을 확인하지 않은 원본 데이터는 커밋하지 않습니다. 회의에서 정하지 않은 내용은 '검토 중'으로 구분합니다.
