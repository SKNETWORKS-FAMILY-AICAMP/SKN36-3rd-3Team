# SKN36-3rd-3Team

## 고령층을 위한 친절한 정책 안내 RAG 챗봇

고령층이 복잡한 정책·복지 정보를 쉬운 말로 이해할 수 있도록 돕는 팀 프로젝트입니다. 공식 정책 문서와 데이터셋·API에서 필요한 근거를 검색한 후 답변하는 RAG(Retrieval-Augmented Generation) 방식을 활용할 예정입니다.

현재는 기획 및 데이터 조사 단계입니다. 챗봇 구현, 데이터 확보, 모델 선정은 아직 완료되지 않았습니다.

## 목표와 답변 원칙

- 정책의 지원 대상, 지원 내용, 신청 방법과 문의처를 쉽게 설명합니다.
- 지역·연령·신청 기간 등 조건을 확인하고, 모르는 조건은 추가 질문합니다.
- 답변에 공식 출처 링크와 자료 기준일을 표시합니다.
- 검색 근거가 부족하거나 오래된 경우 확인이 필요하다고 안내합니다.
- 수급 자격을 임의로 확정하지 않고 공식 기관의 최종 확인을 안내합니다.
- 큰 글씨, 짧은 문장, 단계별 안내를 고려합니다. 구체적인 화면 구성은 팀 회의에서 결정합니다.

## 예정 처리 흐름

공식 데이터 수집 → 정제 및 출처 기록 → 문서 분할 → 임베딩 및 검색 인덱스 구성 → 질문 관련 근거 검색 → 쉬운 말로 답변 및 출처 표시


## 협업 방법

1. 회의를 하고 나서 회의내용을 확인합니다.
2. 회의내용을 보고 각자 업무에 맞춰서 issue를 생성 및 담당자를 설정합니다.
3. dev에서 feature/이슈번호-작업명 브랜치를 만듭니다.
4. 문서 또는 코드를 작성한 뒤 dev 대상으로 PR을 생성합니다.
5. PR 본문에 관련 이슈를 연결합니다.
6. 리뷰 병합 후 이슈와 보드를 완료 처리합니다.
7. 기본 브랜치가 dev이므로 이슈 자동 종료 여부도 확인합니다.
 
* 주의사항 *
- API 키, 개인정보, 사용 권한을 확인하지 않은 원본 데이터는 커밋하지 않습니다.
- 회의에서 정하지 않은 내용은 '검토 중'으로 구분합니다.

## 데이터 파이프라인 MVP (M0~M2)

기존 XML·PDF와 수동 저장한 시설·복지·FAQ JSON을 공통 JSONL로 변환하는 실행법은 [수집·전처리 안내](docs/data-preprocessing.md)에 정리했습니다. 이 단계는 임베딩·RAG·UI 연결 전의 데이터 준비 작업입니다. 시설·지자체 API 실호출은 승인키와 오퍼레이션 명세 설정·검증이 필요합니다.
