## 2. 업무별 명세

### T1. STT·TTS 구현 · 🟦 진행

**목적:** 어르신이 글자 대신 말로 묻고, 답변을 소리로 들을 수 있게 합니다.

**하는 것 (1차)**
- 브라우저 내장 음성 기능(Web Speech API)을 씁니다. 새 패키지와 백엔드 변경은 없습니다.
- **STT(말 → 글자):** 마이크 버튼을 누르면 한국어를 인식해 입력창에 넣습니다. **자동 전송하지 않고**, 사용자가 확인·수정한 뒤 보냅니다.
- **TTS(글자 → 말):** 답변 카드에 "읽어 주기 / 멈추기" 버튼을 둡니다. 누를 때만 읽습니다.

**안 하는 것**
- 서버형 음성 인식·합성(OpenAI 등). 1차 품질이나 지원 범위가 부족할 때만 2차로 검토합니다.
- 자동 읽기, 음성 녹음 저장.
- 질문 글자 수 제한 변경(현재 300자). 늘리려면 별도로 결정합니다.

**바꾸는 파일**

| 파일 | 내용 |
|---|---|
| `frontend/src/lib/speech.ts` (신규) | 지원 여부 확인, 인식 시작·끝내기·취소, 한국어 목소리 선택, 읽기·멈추기, **지금 읽는 답변 하나만** 관리, 듣는 중에는 읽기 차단 |
| `frontend/src/lib/useSpeechInput.ts` (신규) | 마이크 상태 훅(Home·Chat 공용). 오류 문구, 화면 이탈 시 취소 |
| `frontend/src/components/MicButton.tsx` (신규) | 마이크 버튼(대기·듣는 중·오류·미지원)과 안내 줄(`SpeechStatus`). `type="button"`으로 폼 제출을 막습니다 |
| `frontend/src/components/SpeakButton.tsx` (신규) | 소리로 듣기·읽기 멈추기 버튼 |
| `frontend/src/pages/Home.tsx` | 이미 있는 🎤 자리(비활성, "준비 중")를 실제 마이크 버튼으로 바꿉니다 |

**음성 인식(STT) 동작 규칙**

| 상황 | 동작 |
|---|---|
| 입력창에 이미 글자가 있음 | 기존 글자를 지키고 **뒤에 이어 붙입니다** |
| 말하는 중(중간 결과) | 입력창에 넣지 않습니다. 필요하면 따로 "듣는 중" 표시만 합니다 |
| 인식이 확정됨(`isFinal`) | **한 번만** 입력창에 넣습니다 |
| 듣는 중에 사용자가 글자를 고침 | 고친 최신 입력을 기준으로 이어 붙입니다 |
| "말하기 끝내기" 버튼 | `stop()`: 마지막 인식 결과까지 받습니다 |
| 새로 시작·페이지 이탈·취소 | `abort()`: 결과를 버리고, 늦게 도착한 결과가 입력창에 들어오지 않게 합니다 |
| 듣는 중 | 보내기 버튼을 잠시 막습니다. 듣기가 끝난 뒤 확인하고 보냅니다 |
| 300자 초과 | 기존 입력을 지키고 길이 안내를 표시합니다. 몰래 잘라 내지 않습니다 |

**읽어 주기(TTS) 동작 규칙**
- 한 번에 **한 답변만** 읽습니다. 다른 답변을 읽거나 마이크를 켜거나 페이지를 떠나면 기존 읽기를 멈춥니다. 마이크가 읽는 소리를 다시 인식하지 않게 하려는 것입니다.
- `speechSynthesis.cancel()`은 모든 읽기를 멈추므로, 다른 카드의 버튼 상태도 같이 "읽어 주기"로 되돌립니다.
- 한국어 목소리 목록이 늦게 준비될 수 있습니다. 무한정 기다리지 않고, 준비가 안 되면 안내와 다시 시도를 제공합니다.
- 읽을 때 본문은 그대로 두고, 마크다운 기호·URL·내부 ID만 정리합니다.

**읽어 주기 대상 (1차)**

| 답변 종류 | 읽기 버튼 | 이유 |
|---|---|---|
| `success` 답변 | ✅ | 기본 답변 |
| `no_evidence` 되묻기 | ✅ | 무엇을 더 말해야 하는지 들어야 합니다 |
| `safety_response` 긴급 안내 | ✅ | 가장 중요한 안내입니다. 카드 코드가 따로 분기되어 있어 별도로 넣습니다 |
| `error` | ❌ | 짧은 오류 문구라 1차에서는 제외합니다 |
| 후속 질문(`followUp`) | ❌ | 카드 없이 선택 버튼으로만 표시되므로 1차에서는 제외합니다 |

**예외 동작**

| 상황 | 동작 |
|---|---|
| 브라우저 미지원 | 마이크 버튼 대신 "이 브라우저에서는 음성 입력을 쓸 수 없어요" 안내. 글자 입력은 그대로 |
| 마이크 권한 거부 | 권한 허용 방법 안내. 글자 입력은 그대로 |
| 소리가 안 들림·인식 실패 | 기존 입력을 유지하고 다시 말하기를 안내 |
| 한국어 목소리 없음 | 읽기 버튼에 안내를 표시하고, 글자 답변은 그대로 |
| 보안 연결이 아님 | 마이크는 `localhost`나 `https`에서만 동작한다고 안내 |

**개인정보 안내:** 브라우저에 따라 음성이 외부 서버로 전송될 수 있습니다. 마이크 옆에 "이름·전화번호·주민번호는 말하지 마세요"라고 안내합니다.

### T6. LLM 연결 · ⬜ 대기

**선행 작업:** 4차 RAG 결과, T5

**하는 것**
- 새 RAG 반환 형식 확인, 필요하면 변환(`src/agents/welfare_retrieval.py`)
- 잘못된 문의처는 **검색 결과를 받자마자** 제외합니다. 근거 검사 전에 처리하고, 원본 값과 제외 사유는 남깁니다. 프롬프트 지침은 보조 방어로만 씁니다.
- Neo4j 신청 방법·출처를 근거 검사(`evidence_check.py`), 답변(`welfare_answer.py`), 지침(`prompts.py`), 출처 표시에 연결합니다.
- 실제 LLM 시험은 **확인된 실제 정책 몇 건**으로 합니다. 테스트(mock) 자료는 코드가 LLM 호출을 막으므로, 이 차단을 풀지 않습니다.

**완료 기준**

- [ ] 신청 방법이 없는 정책은 지어내지 않고 "확인 필요"로 안내합니다.
