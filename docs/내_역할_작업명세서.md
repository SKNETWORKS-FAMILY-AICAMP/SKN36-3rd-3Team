## 2. 업무별 명세

### T1. STT·TTS 구현 · 🟦 진행

**목적:** 어르신이 글자 대신 말로 묻고, 답변을 소리로 들을 수 있게 합니다.

**하는 것 (1차)**
- 브라우저 내장 음성 기능(Web Speech API)을 씁니다. 새 패키지와 백엔드 변경은 없습니다.
- **STT(말 → 글자):** 마이크 버튼을 누르면 한국어를 인식해 입력창에 넣습니다. **자동 전송하지 않고**, 사용자가 확인·수정한 뒤 보냅니다.
- **TTS(글자 → 말):** 답변 카드에 "읽어 주기 / 멈추기" 버튼을 둡니다. 누를 때만 읽습니다.

**안 하는 것**
- 서버형 음성 인식·합성(OpenAI 등). 1차 품질이나 지원 범위가 부족할 때만 2차로 검토합니다.
- 자동 읽기, 음성 녹음 저장.
- 질문 글자 수 제한 변경(현재 300자). 늘리려면 별도로 결정합니다.

**바꾸는 파일**

| 파일 | 내용 |
|---|---|
| `frontend/src/lib/speech.ts` (신규) | 지원 여부 확인, 인식 시작·끝내기·취소, 한국어 목소리 선택, 읽기·멈추기, **지금 읽는 답변 하나만** 관리, 듣는 중에는 읽기 차단 |

**음성 인식(STT) 동작 규칙**

| 상황 | 동작 |
|---|---|
| 입력창에 이미 글자가 있음 | 기존 글자를 지키고 **뒤에 이어 붙입니다** |
| 말하는 중(중간 결과) | 입력창에 넣지 않습니다. 필요하면 따로 "듣는 중" 표시만 합니다 |
| 인식이 확정됨(`isFinal`) | **한 번만** 입력창에 넣습니다 |
| 듣는 중에 사용자가 글자를 고침 | 고친 최신 입력을 기준으로 이어 붙입니다 |
| "말하기 끝내기" 버튼 | `stop()`: 마지막 인식 결과까지 받습니다 |
| 새로 시작·페이지 이탈·취소 | `abort()`: 결과를 버리고, 늦게 도착한 결과가 입력창에 들어오지 않게 합니다 |
| 듣는 중 | 보내기 버튼을 잠시 막습니다. 듣기가 끝난 뒤 확인하고 보냅니다 |
| 300자 초과 | 기존 입력을 지키고 길이 안내를 표시합니다. 몰래 잘라 내지 않습니다 |

**읽어 주기(TTS) 동작 규칙**
- 한 번에 **한 답변만** 읽습니다. 다른 답변을 읽거나 마이크를 켜거나 페이지를 떠나면 기존 읽기를 멈춥니다. 마이크가 읽는 소리를 다시 인식하지 않게 하려는 것입니다.
- `speechSynthesis.cancel()`은 모든 읽기를 멈추므로, 다른 카드의 버튼 상태도 같이 "읽어 주기"로 되돌립니다.
- 한국어 목소리 목록이 늦게 준비될 수 있습니다. 무한정 기다리지 않고, 준비가 안 되면 안내와 다시 시도를 제공합니다.
- 읽을 때 본문은 그대로 두고, 마크다운 기호·URL·내부 ID만 정리합니다.

**읽어 주기 대상 (1차)**

| 답변 종류 | 읽기 버튼 | 이유 |
|---|---|---|
| `success` 답변 | ✅ | 기본 답변 |
| `no_evidence` 되묻기 | ✅ | 무엇을 더 말해야 하는지 들어야 합니다 |
| `safety_response` 긴급 안내 | ✅ | 가장 중요한 안내입니다. 카드 코드가 따로 분기되어 있어 별도로 넣습니다 |
| `error` | ❌ | 짧은 오류 문구라 1차에서는 제외합니다 |
| 후속 질문(`followUp`) | ❌ | 카드 없이 선택 버튼으로만 표시되므로 1차에서는 제외합니다 |

**예외 동작**

| 상황 | 동작 |
|---|---|
| 브라우저 미지원 | 마이크 버튼 대신 "이 브라우저에서는 음성 입력을 쓸 수 없어요" 안내. 글자 입력은 그대로 |
| 마이크 권한 거부 | 권한 허용 방법 안내. 글자 입력은 그대로 |
| 소리가 안 들림·인식 실패 | 기존 입력을 유지하고 다시 말하기를 안내 |
| 한국어 목소리 없음 | 읽기 버튼에 안내를 표시하고, 글자 답변은 그대로 |
| 보안 연결이 아님 | 마이크는 `localhost`나 `https`에서만 동작한다고 안내 |

**개인정보 안내:** 브라우저에 따라 음성이 외부 서버로 전송될 수 있습니다. 마이크 옆에 "이름·전화번호·주민번호는 말하지 마세요"라고 안내합니다.

### T6. RAG 구축·LLM 연계 · ⬜ 대기

**선행 작업:** 실제 수정본의 임베딩·적재 전에는 T5를 통과합니다. 검색 코드·적재 도구·평가 준비는 데이터 도착 전에도 할 수 있습니다. 사용자의 담당은 기존 LLM 연결에서 RAG 구축으로 변경됐으며, 재개 시 6장 메모를 먼저 확인합니다.

**하는 것**

### 지역 검색

- 정식 시도명은 전남광주통합특별시, 원문은 raw_*에 보존. 옛 전남/광주 경계는 적용 근거와 이력이며 통합시 전체 적용으로 확대하지 않는다.
- 전남/전라남도/광주광역시 등 입력 별칭을 공통 함수로 정규화한다. '광주' 단독은 모호하며 경기도 광주시와 혼동하지 않는다. 교육청과 '-'는 시군구가 아니다.
- 행정 등록 지역과 실제 정책 적용 지역을 구분한다. applies_to, scope_status, scope_basis를 함께 사용하고 candidate를 확정 자격으로 말하지 않는다.

- 추천 설계(구현 전): 지역 검색 + 전국 검색(질문 벡터 1회 재사용), ID 중복 제거, 공통 후필터. 전국 PDF는 빈 지역이 아니라 검증된 national 범위로 포함한다.

### Neo4j 조회와 LLM 연결

- 2026-11-27 사용자 결정: 추가 LLM 안전 판단은 RAG 구축 후 LLM 담당자에게 인계한다. 현재 정규식의 한계, 기존 코드 수정 요청, 연결 규칙과 완료 기준은 [LLM 담당자 인수인계](LLM_담당자_인수인계.md)에 기록했다. 추가 LLM 유예와 기존 긴급 분기 오류 수정은 별개이며, 실제 사용자 대상 시연·운영 전 전체 안전 경로를 확인한다.
- 우선 목적은 policy_id 기반 신청 방법·문의처·출처 조회. 정책 간 관계 확장, EXCLUDES, 복합 수급 Rule Engine 전체 구축은 별도 확장 과제이며 이번 필수 구현으로 간주하지 않는다.
- 그래프 application의 application_text/application_method_name/application_required/application_basis 네 칸은 최종 정책 값을 그대로 복사했다. false/null, 선행 조건이 포함된 근거 문장을 보존한다.
- 현재 적재 노트북은 그래프 JSONL을 직접 읽지 않는다. RAG 담당이 application, regions, 조건을 Neo4j에 적재·조회하도록 연결해야 한다. 객체/객체목록을 노드 속성에 그대로 SET하지 말고 명시적으로 변환한다.
- RagABPolicy/RagABFixedChunk/RagABSection/RagABDocument와 CHUNK_OF/HAS_SECTION 등 기존 라벨·관계를 확인해 활용한다. policy_id만으로 모든 노드를 MATCH하면 정책 청크까지 잡을 수 있으므로 정책 라벨·활성 버전을 명시한다.
- src/agents/welfare_answer.py의 graph_facts는 현재 ID/발견 여부/제목 위주다. 조회한 신청 정보·출처를 근거 검사와 최종 LLM 입력·출처 표시까지 전달해야 한다.
- 기존 그래프 46개 정책의 연령 raw_text가 문자열 대신 목록인 상태는 보존됐다. 조회 어댑터에서 두 형식을 다루거나 별도 정규화를 합의한다.
- Need·나이·조건의 needs_review는 자격 검증 완료가 아니다. 관계 없음은 중복 수급 가능의 근거가 아니다.
- PostgreSQL은 현재 대화 기록용이며 정책 검색용 SQL DB를 새로 전제하지 않는다.
