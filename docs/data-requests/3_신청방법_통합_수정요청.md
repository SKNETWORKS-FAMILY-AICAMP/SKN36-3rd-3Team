### 0-3. 변경 목록 형식 (확정)

- 위치: `data/staging/local_welfare/<작업일 YYYY-MM-DD>/changes/`

- 한 줄 = 한 정책의 한 칸 변경

```json
{"policy_id": "local:WLF00004288", "field": "application_required", "old": null, "new": false, "basis": "신청 본문 '별도 신청 절차 없음'", "checked_at": "2026-11-27", "base_version": "nationwide_2026_11_25_84d46d570a5b"}
```

`field`는 0-2b의 **내 담당 칸**만 씁니다. `old`는 기준 버전의 현재 값과 같아야 합니다. `basis`가 비면 안 됩니다. 기존에 없던 통합시 신규 정책은 0-4b 절차를 따릅니다.

| 항목 | 내용 |

| 처리 | 문구를 확인한 뒤 `application_required=false`, `application_basis.quote`에 근거 문장 |
| 선행 조건 | "한부모가족으로 **결정된 가구에게** 별도 신청 절차 없이 지급"(WLF00002339)처럼 **대상자 결정이 먼저 필요한** 경우가 있습니다. `quote`에 선행 조건까지 넣어 "신청 안 해도 받는다"로 읽히지 않게 해 주세요 |
| 금지 | **원문에 명시된 건만** 표시합니다. 빈칸 전체를 "신청 없음"으로 채우지 않습니다 (가이드 §5 "신청 방법 미기재 ≠ 신청 불필요") |
| 나머지 14건 | 본문에 방문·인터넷·우편 등 방식이 **분명히 적힌 경우만** 방식명을 추출하고, 아니면 빈칸 유지 |

| 버전 | 새 `data_version` 하나로 모든 파일 통일. 형식 `nationwide_YYYY_MM_DD_<해시12>` |
| 해시 계산 (확정) | 대상: `policy_chunks.jsonl`, `guideline_chunks.jsonl`, `policy_graph_entities.jsonl`. 각 레코드에서 **최상위와 `metadata` 안의 `data_version`을 모두 뺀 뒤** `json.dumps(sort_keys=True, ensure_ascii=False, separators=(",", ":"))`로 직렬화하고 **각 레코드의 UTF-8 바이트 뒤에 LF 1바이트(0x0A)를 추가**. 파일 안은 `chunk_id`(그래프는 `policy_id`) 순 정렬, 위 파일 순서로 이어 붙여 SHA-256 → 앞 12자리. 같은 입력이면 항상 같은 버전이 나와야 합니다 |
