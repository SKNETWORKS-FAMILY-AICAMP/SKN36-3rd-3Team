## 2. 전처리 과정과 품질 관리 기준

```text
지자체 API → 목록·상세 병합 → 값 정규화 → 지역·노인 관련성 선별 → 정책 574건 ───┐
                                                                               ├→ 같은 입력으로 A/B 청킹
PDF 4종   → 페이지 추출·교정 → 장·절 단위 통합 → 섹션 선별 → 섹션 1,189건 ─────┘
```

### 2.1 API 정책의 중복·결측·관련성

| 문제 상황 | 적용 기준 | 확인 결과 |
| --- | --- | --- |
| 같은 사업이 조회 결과에 반복될 수 있음 | 원본 사업 ID(`servId`)를 중복 판단 기준으로 삼았다. 상세 조회 ID를 먼저 고유화하고 상세 캐시를 재사용한다. 병합용 상세 행에 동일 ID가 있으면 마지막 행을 남긴다. 정규화·선별 입력의 ID가 비어 있거나 중복되면 오류로 처리한다. 사업명이 비슷해도 ID가 다르면 제목만으로 병합하지 않는다. | 11월 7일 파일의 1,485건과 최종 정책 574건은 각각 파일 내 ID가 모두 고유하다. 실행별 실제 중복 제거 건수는 확인되지 않았다. |
| 목록 페이지 또는 상세 응답이 없거나 잘못됨 | 페이지 번호·총건수·빈 페이지·응답 코드를 점검하고 HTTP 호출 제한과 XML 파싱 오류를 기록하도록 구성했다. 상세 조회에 실패한 경우 목록 행을 남기고 `detail_fetched=false`로 표시한다. | 11월 7일 스냅샷은 상세 1,000건, 미확보 485건이다. 최종 선별본 574건에서는 상세 플래그가 모두 참이다. 이 값으로 개별 필드가 모두 채워졌는지는 판단할 수 없다. |
| 정책 필드가 비었거나 형식이 다름 | 사용 가능한 상세값을 우선하고 목록값으로 보완하며 선택한 출처를 기록한다. 빈 값은 `null`, 분류는 배열로 정규화한다. 날짜는 해석 가능한 경우 ISO 형식으로 변환하고 원문 값을 보존한다. 검색 본문은 사업명·지원 대상·선정 기준·지원 내용 등의 항목으로 만들며 값이 없는 항목은 생략한다. | 574건에서 지원 대상·선정 기준·지원 내용·출처 URL의 빈 값은 0건이다. 신청 방법 본문은 97건, 신청 방식명은 138건, 지역 코드는 574건이 비어 있다. 두 신청 필드는 따로 집계했다. 종료일 `9999-12-31`이 553건에 있어 이 값으로 시행 종료 여부를 확정할 수 없다. |
| 대상 지역이 모호하거나 시군구가 없음 | 상세·목록·요청 지역을 대조하고, 전남·광주 통합 표기는 시군구와 정책명·대상 문구를 함께 본다. 서울·경기·전남 및 전국 후보를 선택 범위로 두고 광주·판단 불가 후보는 분리할 수 있다. 원문 지역값과 미확정 상태를 보존한다. | 시군구가 잠정 분류된 정책은 521건, 범위가 미확정인 정책은 53건이다. 전남 라벨 중 2건의 정규화 시도명에 통합특별시 표기가 남아 있다. |
| 대상이 노인인지 단순 언급인지 모호함 | 정책명·지원 대상·선정 기준 등에서 노인이나 연령 요건이 확인되면 직접 관련으로 분류한다. 저소득·의료·주거 등 공통 지원은 간접 관련으로 포함한다. 본문에만 노인 관련 표현이 있거나 연령 제한 등 조건이 상충하면 검토로 보낸다. 아동·청소년·임신 등 전용 단서가 있고 포함 근거가 없으면 제외 후보로 분리한다. | 최종본은 직접 227건과 간접 347건이다. 지역 선별과 노인 자격은 574건 모두 공식 확인 플래그가 미확인이다. 자동 분류 결과는 검색 범위를 정하는 데 쓰며, 개인별 자격은 원문 조건을 확인해야 한다. |

**결측 처리 사례.** 서울 종로구의 ‘지역사회 복지자원 연계활성화’(`WLF00002480`)는 상세 수집에 성공했지만 신청 방법 본문과 신청 방식명이 모두 비어 있었다. 정책 문서와 검색 청크는 사업명·지역·지원 정보를 유지했고, 신청 항목은 생략했다. 이 청크에서 신청 경로를 확정할 수 없다는 점이 결측을 그대로 남기는 이유다.

별도 시설 자료는 조회 범위를 시도 경계 사각형으로 잡은 뒤 실제 행정경계 안과 경계선 위에 있는 좌표를 남겼다. 시설 ID로 중복을 제거하고 ID를 사용할 수 없을 때는 전체 행을 비교하도록 했다. 저장본 164건은 시설 ID가 고유했고 좌표·연락처 빈 값은 없었다.

### 2.2 PDF 텍스트·표·이미지와 문서 구조

| 문제 상황 | 적용 기준 | 확인 결과 또는 남은 범위 |
| --- | --- | --- |
| 줄 순서가 뒤바뀌거나 본문·수치가 누락됨 | 페이지별 추출문과 원본 렌더링을 함께 비교한다. 수정할 문자열을 원문에서 찾아 교정하며, 불확실한 내용은 임의로 채우지 않는다. 별도 감사에서 수정 후보를 확인하고 영향을 받은 페이지를 다시 대조하도록 했다. | 4개 원본의 물리 페이지 1,506쪽 가운데 추출 JSON에 페이지 레코드 1,404개가 남았다. 레코드에 없는 102쪽의 개별 사유는 확인되지 않았다. |
| 표 헤더·행·열 또는 병합 셀의 대응이 틀림 | 행과 열의 대응, 머리글·단위·각주를 원본 이미지와 대조한다. 복잡한 표는 텍스트 변환에 더해 이미지로 남겨 배치를 확인할 수 있게 한다. | 별도 표본 실행에서 노인일자리 표의 병합 셀 오류를 확인해 교정했다. 표본 사례는 아래에 제시한다. |
| 그림의 배치·화살표 의미가 텍스트 추출에서 사라지거나 이미지가 잘못된 항목에 붙음 | 필요한 표·도식 영역을 PNG로 잘라 저장한다. 섹션에 상대 경로와 설명을 붙이고, 분할·병합 후 이미지 소속과 참조를 대조한다. | 최종 섹션에 이미지 참조 249건이 있으며 고유 경로 248개가 모두 실제 파일로 연결됐다. 파일 존재 검사는 각 이미지의 배치·내용을 검증하는 것과 구별된다. |
| 페이지 단위 추출이 문단을 자르거나 서로 다른 항목을 섞음 | 제목과 줄 위치를 확인해 한 페이지에 있는 서로 다른 항목을 나누고, 다음 페이지로 이어지는 항목은 하나의 섹션으로 연결한다. 장·절·소절과 PDF 물리 페이지 범위를 남긴다. | 선별 전 1,228섹션, 선별 후 1,189섹션이다. 페이지와 섹션은 집계 단위가 달라 한 페이지가 여러 섹션에 포함될 수 있다. |
| 문서 안에 대상과 무관한 항목이나 같은 맥락의 반복이 있음 | 근거 구절을 확인해 명백히 무관하거나 같은 맥락에서 고유 정보 없이 반복되는 항목만 제외 후보에 올린다. 요약과 상세 지침이 서로 다른 정보를 제공하거나, 금액·조건·이미지를 잃을 수 있거나, 판단이 불확실하면 유지한다. | 종합 안내서에서만 39섹션이 빠졌다. 청소년·청년 지원 18건, 임신·보육지원 10건 등이 포함되며, 남은 1,189섹션의 필드는 선별 전후 동일했다. 39건 각각의 판정 로그는 확인되지 않아 중복으로 제거된 건수는 따로 집계할 수 없다. |

## 3. 문서 분할 및 A/B 실험

A/B의 목적은 같은 내용에서 **분할 경계를 정하는 방식이 근거 검색에 어떤 차이를 만드는지** 비교하는 것이다. 두 방식은 동일한 정책 574건과 PDF 섹션 1,189건을 사용하며, 한 청크가 서로 다른 정책 또는 섹션의 경계를 넘지 않는다. PDF의 페이지 추출과 섹션 구성은 두 방식에 공통이다.

| 실험군 | 분할 방식 | 문맥 보존과 한계 |
| --- | --- | --- |
| `A_fixed` | 최대 800자의 고정 창으로 잘라 650자씩 이동한다. 이어지는 창에 앞 창의 150자가 겹친다. 마지막 창은 남은 길이만 사용한다. | 일정한 비교 기준이며 경계 주변을 겹쳐 담는다. 문장·정책 항목·표 행 중간에서도 분할될 수 있다. |
| `B_structure` | 정책 본문은 지원 대상·선정 기준·지원 내용 등의 라벨로, PDF 본문은 문단을 우선하고 필요 시 줄로 나눈다. 단위를 최대 800자까지 묶는다. 긴 단위를 분할할 때는 줄바꿈·문장 끝을 우선하고 150자를 겹친다. | 항목과 값, 주변 문맥이 함께 남도록 한다. 150자 중첩은 긴 단위 분할에 적용되며, 모든 청크에 동일한 중첩이 있는 것은 아니다. 80자 미만 조각을 병합·재배치하는 규칙은 휴리스틱이며 긴 표의 구조 보존을 보장하지 않는다. |

| 실험군 | 자료 유형 | 부모 수 | 청크 수 | 최소 / 평균 / 최대 문자 수 |
| --- | --- | ---: | ---: | ---: |
| `A_fixed` | 정책 | 574 | 662 | 149 / 484.42 / 800 |
| `A_fixed` | PDF 섹션 | 1,189 | 2,738 | 76 / 626.21 / 800 |
| `B_structure` | 정책 | 574 | 675 | 85 / 456.96 / 800 |
| `B_structure` | PDF 섹션 | 1,189 | 3,190 | 75 / 499.29 / 800 |

`A_fixed`는 **3,400청크**, `B_structure`는 **3,865청크**다. 차이 465건 중 452건이 PDF에서 발생했다. A/B의 부모 문서 집합은 동일하며 전략별 JSONL과 별도 청크 ID로 실험을 관리했다.

**후속 검색 비교.** 두 청킹 방식과 두 임베딩 모델을 같은 질문 세트에서 비교했다. 지역 필터를 켜고 정답 근거가 있는 113건을 채점했으며 지역 오추천 등을 보는 함정 질문 9건은 별도로 집계했다. 아래 표의 `Hit@5`는 상위 5개 결과에 정답 근거가 나온 비율이고, `MRR@5`는 첫 정답 근거 순위의 역수를 평균한 값이다.

| 임베딩 모델 | A Hit@5 | B Hit@5 | A MRR@5 | B MRR@5 |
| --- | ---: | ---: | ---: | ---: |
| KURE-v1 | 0.885 | 0.858 | 0.765 | 0.713 |
| Qwen3-Embedding 0.6B | 0.770 | 0.779 | 0.606 | 0.596 |

KURE-v1에서는 A가 두 지표에서 높았다. Qwen에서는 B의 `Hit@5`가 높고 A의 `MRR@5`가 높았다. 이 실험은 해당 질문 세트에서 근거를 얼마나 잘 찾는지 측정했으며, 답변 정확성이나 실제 이용자의 다양한 질문까지 평가한 결과는 아니다. [검색 실험 PR](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN36-3rd-3Team/pull/24)

## 4. 메타데이터 및 출처 추적

청크 JSONL은 한 줄에 본문과 메타데이터를 함께 저장한다. 검색에서 본문 일부가 반환되어도 해당 청크의 부모 정책·PDF 섹션을 찾고 출처와 적용 범위를 확인할 수 있다.

| 필드 | 의미와 검색에서의 활용 |
| --- | --- |
| 최상위 `text`, `chunk_id`, `id` | `text`는 검색 본문이다. `chunk_id`는 자료 유형·부모 ID·청킹 전략·순번을 조합한다. 같은 청크 ID에서 항상 같은 UUID(`id`)가 생성되므로 결과 재생성, 중복 검사와 파일 간 대조에 쓴다. |
| `metadata.record_type`, `parent_id`, `chunk_strategy` | 정책·PDF를 구분하고 검색 결과를 부모 문서로 연결한다. A/B는 부모 ID를 공유하고 청크 ID는 전략마다 다르다. |
| `metadata.title`, `source_type`, `source_url` | 출처 유형과 제목을 표시한다. 정책 574건에는 원본 URL이 있다. PDF 1,189섹션의 URL 값은 `null`이며 파일에 대응하는 `source`와 페이지로 출처를 특정한다. |
| 최상위 `policy_id`, `metadata.serv_id` | 프로젝트 내 정책 ID와 원본 API 사업 ID를 연결한다. 한 정책이 여러 청크로 나뉘어도 같은 사업으로 묶을 수 있다. |
| `metadata.sido_name`, `sigungu_name`, `region_scope`, `region_review_status`, `region_selection_verified` | 지역을 기준으로 검색 범위를 좁히고, 잠정·미확정 지역을 구별한다. PDF의 `national`은 안내서 범위를 뜻한다. 개별 제도의 지역 제한은 본문에서 확인한다. |
| `metadata.elderly_category`, `themes`, `target_groups`, `life_stages` | 직접·간접 분류와 주제·대상·생애주기 태그를 제공한다. 태그는 검색에 참고할 수 있으며 지원 자격은 본문 조건을 확인해야 한다. |
| 최상위 `section_id`, `metadata.document_id`, `source`, `chapter`, `section`, `subsection` | PDF 청크를 문서와 장·절·소절로 연결한다. 섹션 ID로 잘리기 전 전체 문맥을 확인할 수 있다. |
| `metadata.page_start`, `page_end`, `images`, `publisher`, `publication_year` | 출처 문서와 물리 페이지 범위, 이미지 경로·설명을 유지한다. 페이지와 이미지는 부모 섹션 기준으로 복사하므로 해당 청크의 문장이 정확히 어느 한 쪽에 있는지는 원본에서 확인한다. |

**실제 정책 청크 예시.** JSONL 한 줄을 읽기 쉽게 펼쳤다. 핵심 필드만 표시하고 `text`는 첫 두 줄을 발췌했다.

```json
{
  "id": "f2ccafae-7b39-557b-9785-4c3f1aadc0b6",
  "chunk_id": "policy::local:WLF00002480::fixed::0001",
  "policy_id": "local:WLF00002480",
  "text": "사업명: 지역사회 복지자원 연계활성화\n지역: 서울특별시 종로구",
  "metadata": {
    "record_type": "policy",
    "parent_id": "local:WLF00002480",
    "chunk_strategy": "fixed",
    "serv_id": "WLF00002480",
    "source_url": "https://www.bokjiro.go.kr/ssis-tbu/twataa/wlfareInfo/moveTWAT52011M.do?wlfareInfoId=WLF00002480&wlfareInfoReldBztpCd=02",
    "sido_name": "서울특별시",
    "sigungu_name": "종로구",
    "region_selection_verified": false
  }
}
```

PDF의 경우 `guideline::welfare_services_2026_p0008_01::structure::0001` 청크의 부모는 `welfare_services_2026_p0008_01`이다. 출처는 「2026 나에게 힘이 되는 복지서비스」, 섹션은 ‘나에게 힘이 되는 안내책자 똑똑하게 활용하세요!’, 인용 범위는 물리 페이지 8–9쪽이다. 이처럼 정책은 원본 사업 ID와 URL, PDF는 문서·섹션 ID와 페이지를 통해 출처를 추적한다.

## 5. 검증 결과와 적재 직전 준비 상태

| 검사 | 확인 결과 |
| --- | --- |
| 정책 문서 재생성 | 최종 선별본 574건으로 정책 문서를 다시 구성한 결과 저장본과 일치했다. 정책 ID 574개는 고유하다. |
| PDF 형식·참조 검사 | 섹션 ID 중복, 필수 출처·본문 누락, 페이지 범위 오류를 검사했다. 1,189섹션에서 오류 0건, 경고 14건이었다. 경고는 제목 또는 섹션명 누락 4건과 12,000자 초과 10건이다. 긴 섹션도 청킹 입력으로 유지했다. 이미지 참조 249건은 별도로 파일 존재 여부를 검사했다. |
| 청크 재생성 및 상호 참조 | 두 전략의 정책·PDF JSONL 4개를 재생성해 저장본과 일치함을 확인했다. 7,265청크 모두 부모를 찾을 수 있었고 빈 청크, 800자 초과, 실험군 간 UUID 충돌은 없었다. 각 파일 안에서 본문이 완전히 같은 청크도 없었다. 의도적인 overlap과 A/B에서 같은 내용이 나오는 경우는 유지한다. |

**준비 상태.** 적재 직전 산출물은 원본과 추출 결과, 정책·PDF 부모 문서, A/B별 청크 JSONL로 구성된다. 작업 환경의 추가 적재 입력 패키지에는 KURE-v1로 생성한 `A_fixed` 청크 ID 3,400개와 1,024차원 벡터가 들어 있다. 검증은 저장 파일을 기준으로 수행했다.

**남은 품질 한계.** 지역·자격이 미확인인 정책은 추천 범위가 넓어지거나 맞는 정책이 필터에서 빠질 수 있다. 신청 정보가 비어 있는 정책은 근거만으로 신청 경로를 안내하기 어렵다. PDF는 전 페이지의 표·수치·자격을 사람이 재검증했다는 기록이 없고, 여러 페이지 섹션은 인용 범위 안에서 다시 위치를 확인해야 한다. 제목이나 내용이 비슷한 API·PDF 레코드의 의미상 중복도 전수 확인되지 않아 같은 제도가 상위 검색 결과에 여러 건 나타날 수 있다.
