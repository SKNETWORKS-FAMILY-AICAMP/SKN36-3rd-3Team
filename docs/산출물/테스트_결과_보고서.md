### T03 · 검색 경로 A/B/C

**핵심 결과.** 최신 로컬 실행에서 세 방식은 같은 순서로 근거를 반환했다. 결합 검색에는 양쪽 결과가 참여했지만 이번 질문과 입력에서는 추가 순위 이점이 관찰되지 않았다. 세 질문 세트 모두에서 결합 검색 시간이 가장 길었다.

**세 검색 방식.** A는 Qdrant에서, B는 Neo4j에서 질문과 비슷한 벡터를 찾는다. C는 두 검색을 각각 실행하고 같은 정책·PDF 섹션을 묶어 양쪽의 순위를 합친다. 평가에서는 세 방식 모두 동일한 `A_fixed`·KURE-v1 입력을 전제로 했다. 실제 서비스의 **Hybrid RAG**는 Qdrant가 찾은 청크에 Neo4j 정책·PDF 관계를 붙여 답변 근거를 보강한다. 양쪽 벡터 순위를 합치는 평가용 C와는 구조가 다르다. [A/B/C 평가 코드 변경](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN36-3rd-3Team/commit/cd99964) · [서비스 검색 변경 이력](https://github.com/SKNETWORKS-FAMILY-AICAMP/SKN36-3rd-3Team/pull/30)

**채점 기준.** v3 기본 검색 122건, ABC 복수 정책·관계 질문 20건, 페르소나별 질문 32건을 각 안에 적용했다. 안별 174행, 총 522행이다. T02가 상위 청크를 채점한 데 비해, 이 실험은 같은 정책·PDF 섹션이 여러 번 나오면 처음 것만 센다. 단일 문항은 상위 5개를 평가한다. 복수 문항의 Recall@10은 찾은 정답 묶음 수 ÷ 전체 묶음 수, Precision@10은 정답 부모 수 ÷ 실제 반환한 상위 10개 이내 부모 수로 문항마다 계산한 뒤 평균한다.

| 질문 세트와 분모 | A·B·C 공통 측정값 | 함정 판정 |
| --- | --- | --- |
| v3 122건, 단일 113건 | Hit@1 0.690, Hit@5 0.894, MRR@5 0.769 | 6/6 통과, 답변 기권 확인 필요 2건 미채점, 시설 문항 1건 제외 |

**순위가 같았던 범위.** 실제 검색한 173문항에서 세 안의 반환 순서가 모두 같았다. 저장된 174행에는 검색에서 제외한 시설 문항 1건도 포함된다. C가 반환한 결과 위치 1,105개 모두에 두 DB의 순위와 Neo4j 근거 확인 표시가 있었다. 같은 벡터와 문서가 순위 일치에 영향을 주었을 가능성이 있다. 두 DB의 후보가 달라지는 질문이나 관계 탐색이 필요한 질문에서는 추가 비교가 필요하다.

**이전 실행과 변경.** `094353`에서는 ABC 묶음 Recall@10이 A/B 0.832, C 0.750이었고 v3 Hit@5는 A/B 0.894, C 0.841이었다. `101732`와 `102722`에서는 ABC Recall@10이 세 안 모두 0.929였다. 함정 분모와 채점 처리도 달라져 개선 폭을 동일 조건의 재평가로 볼 수 없다. 평가 브랜치에는 양쪽 순위를 결합하고 최종 부모 순위와 출처 확인을 남기는 구현이 있다. 최신 CSV에는 그 필드가 있다. 세 실행을 각각 유지하고 하나의 평균이나 동일 설정의 반복으로 집계하지 않았다.

**정답 묶음 누락.** 해남 거주 고령자의 혜택을 묻는 R01에서 세 안 모두 4개 정답 묶음 중 3개를 찾아 Recall@10이 0.750이었다. 독거노인의 갑작스러운 질병·부상에 대한 제도를 묻는 G07은 3개 중 1개만 찾아 0.333이었다. 결과 파일에는 생성 답변이 없으므로 실제로 답변에 빠진 제도 수는 알 수 없다.

**직접 재집계.** 최신 `abc_detail` 522행을 평가 브랜치의 집계 코드로 읽어 `abc_summary` 9행과 비교했고 모든 값이 일치했다. 이 검증은 저장된 상세 점수로 요약을 다시 계산하는 범위였다.

## 3. 데이터·기능 및 운영 검증

### T05 · 질문 API와 응답 형식

상태 확인 함수는 `ok`를 반환했다. `CHAT_API_MOCK=true`에서 정상 질문은 모의 응답과 `no_evidence` 상태, 빈 출처를 반환했다. 빈 문자열·2,001자·잘못된 세션 UUID는 요청 모델에서 거절됐고, 공백만 있는 질문은 처리 함수에서 422 예외가 발생했다. 인프로세스 HTTP 호출 시도는 응답이 완료되지 않아 중단했다. 여기서 확인한 범위는 요청·응답 모델과 요청 처리 함수다.

**재현된 결함 — 확인 질문 선택지 누락**

1. **목적과 기대 결과** — 어르신에게 추가 정보를 물을 때 선택지 두 개를 화면에 제공할 수 있도록 API 응답에 전달하는지 확인한다.
2. **관찰과 원인** — 모의 실행에서 확인 질문이 ‘생활비’와 ‘돌봄’ 선택지 두 개를 생성했다. 이 결과를 API 처리 함수에 넘기자 최종 응답 데이터에는 선택지 목록이 없었다. API 응답 형식에 `choices` 필드가 정의되지 않은 것이 확인됐다.
3. **후속 조치와 재검증** — API 응답 형식과 화면의 선택지 표시를 연결한다. 수정 후 선택지 있는 응답과 없는 응답을 모두 보내고, 실제 HTTP 응답과 화면에서 각각 목록과 버튼이 맞게 표시되는지 확인한다. 이 수정과 재검증의 결과는 확보되지 않았다.

### T06 · 근거 부족 대응 및 출처

문서가 없으면 판정 모델을 호출하지 않고 근거 부족으로 분기했다. 잘못된 판정 응답은 불확실로 분류해 대체 안내로 보냈고, 충분 판정은 답변 경로로 보냈다. 가상 문서는 출처에서 제외됐으며 PDF 예시의 문서 ID와 물리 페이지 4–5가 보존됐다. 모의 입력 5건이 기대대로 동작했다. 실제 문서의 근거 충분성이나 최종 답변의 정확성을 채점한 결과는 T08의 확인 범위다.

### T07 · 세션 기억 및 저장 제한

잘못된 UUID 거절, 새 UUID 생성과 저장, 동일 세션의 최근 이력 조회, 안전 우선 응답의 저장 생략, 답변 오류의 저장 생략을 가상 저장·조회 함수로 검증했다. 5건이 통과했고 T01의 단위 테스트를 합친 재실행은 6/6 통과했다. 실제 PostgreSQL 저장과 이력 조회 결과는 확인되지 않았다.

### T08 · 실제 답변 정확성 및 근거 적합성

페르소나 32문항에는 기준 답변과 근거 문맥이 있다. 저장 CSV는 검색 순위와 정답 부모 ID를 채점했다. 생성 답변의 자격·금액·신청 방법 정확성, 질문 관련성, 근거 충실도(Faithfulness), 출처 적합성에 대한 실측값은 확인되지 않았다. 실제 답변과 평가 모델의 버전, 질문별 판정 기록도 추가 확인이 필요하다.

### T09 · 오류 처리 및 운영 안정성

**모의 오류 처리.** 내부 예외와 답변 오류 상태를 주입해 각각 503 예외로 변환되는 것을 확인했다. 내부 예외 메시지에 넣은 모의 표식은 공개 오류 메시지에 없었다. 이 검사는 핸들러의 처리 범위를 확인했다. 작업 당시 로컬 Qdrant·Neo4j·PostgreSQL 포트에서 연결을 확인하지 못했다. 운영 DB 장애 복구, 실제 OpenAI 응답, 인증·접근 권한과 민감정보 보호의 전 구간 검증은 확인되지 않았다. LLM 답변 생성, 요청 전송, 동시 부하가 포함된 전체 응답 시간과 운영 성공률도 측정값이 확인되지 않았다.
