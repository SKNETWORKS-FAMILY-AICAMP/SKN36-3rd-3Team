# 전국 복지데이터 통합·검증 및 임베딩 인계 기록

2026-11-25 기준으로 **1~3단계 원본 범위 확정, 경기 상세 병합, 통합 데이터 품질 검사**를 완료했다. 통합 원본에는 **15개 시도, 고유 `servId` 4,278개**가 있다. 기존 전남 라벨 정책 **149건**은 후속 정규화에서 지역 판정을 이어받을 수 있도록 보존했다.

`data/`로 시작하는 경로는 저장소 루트 기준이다. 작업 기준은 [오류 검증 보고서](../data/raw/local_welfare/local_welfare_service_outputs/전국_복지데이터_오류_검증_2026-11-25.md)와 [메타데이터 설계 및 DB 연계 가이드](RAG_메타데이터_설계_및_DB_연계_가이드.md)를 참고했다.

팀 인수인계에 따르면 신규 12개 지역을 수집하기 전 상세 수집이 덜 된 곳은 경기도였고, 전남·광주 구분에는 정책 내용 기반 지역 매칭을 사용했다. 저장소에서 확인한 선별본에는 통합 원본에 없는 전남 라벨 149건의 지역값과 판정 필드가 남아 있다. 이 중 147건은 기존 시군구 메타데이터, 2건은 미확인 자동 후보가 판정 출처로 기록돼 있고, 149건 모두 `region_selection_verified=false`다. 기존 판정과 확인 상태를 후속 정규화에 전달하기 위해 149건을 원래 레코드 구조로 보존했다.

**이 단계의 산출물**

- 기존 선별본 574건을 원본 ID와 대조해, 현재 원본에서 찾을 수 없는 전남 라벨 149건을 추출했다. 이 레코드로 [`legacy_jeonnam_selected.jsonl`](../data/staging/local_welfare/2026-11-25/legacy_jeonnam_selected.jsonl)을 만들었다.
- 채택한 원본의 경로·건수·SHA-256과 10개 사본의 대조 결과는 최종 [`validation_report.json`](../data/staging/local_welfare/2026-11-25/validation_report.json)의 `inputs`와 `identical_copies_excluded_as_inputs`에 기록했다.

## 2. 경기 상세 병합

1. 원본과 보완 파일에서 `servId`의 누락·중복을 검사했다. 원본의 `detail_fetched=false`인 경기 485건과 보완 파일의 ID 집합이 정확히 일치했고, 보완 파일의 상세 플래그와 상세 시도가 각각 `true`, `경기도`인 것을 확인했다.
2. ID가 같은 행에서 비어 있는 `detail_*` 필드에 보완 파일의 비어 있지 않은 값을 채우고 `detail_fetched=true`로 갱신했다. 상세값 **9,917개**를 추가했다. 원본의 목록 필드, 이미 채워진 상세값과 행 순서를 보존했다.
3. 경기 보완 후 기존 원본은 **1,485건**을 유지했다. 기존 원본과 신규 지역 간 ID 중복이 0건인 것을 확인한 뒤 신규 **2,793건**을 추가했다. 저장된 파일을 다시 읽어 원본과 필드별로 대조했고, 경기 보완 대상 외의 행과 신규 행이 입력과 일치함을 확인했다.

**이 단계의 산출물**

- 경기 보완 ID 485개가 모두 일치하고 기존·신규 원본 간 ID가 겹치지 않는 것을 확인한 뒤, 경기 보완이 반영된 기존 1,485건과 신규 2,793건을 합쳐 [`merged_policies_raw.jsonl`](../data/staging/local_welfare/2026-11-25/merged_policies_raw.jsonl) **4,278행**을 만들었다.
- 경기 복구 ID와 필드별 추가 건수는 최종 검증 보고서의 `merge`에 기록했다. 경기 보완 결과는 통합 JSONL의 앞 1,485행에 들어 있다.

`detail_fetched`는 상세 확보 상태를 나타낸다. 문의처 정규화 시 `inqNum`과 `detail_inqNum`은 조회수로 취급하고, 관련 코드·이름·내용은 배열 위치만으로 연결할 수 없다. 현재 단계에서는 원본에 있는 값과 후속 검토에 필요한 ID를 보존했다.

**이 단계의 산출물**

- 통합 원본과 전남 보존본을 다시 읽어 입력과 대조한 뒤 [`validation_report.json`](../data/staging/local_welfare/2026-11-25/validation_report.json)을 작성했다. 1단계의 입력 목록과 2단계의 병합 내역에 더해, 3단계의 시도별 집계·결측·충돌·동명 후보와 해당 ID를 `quality`에, 파일 재검증 결과를 `verification`에 담았다.
